# 多环境、多条目与设备授权

用户于 2026-09-16 确认初版，并于 2026-09-18 将条目规则调整为每个环境最多一条；本文件以下述最新规则为准。桥和应用的实现已落在本地工作区，完成下述自动化验证，尚未发布或操作线上数据库。

## 已确认的产品规则

- 普通用户最多两条：国内 PRD `app.seenzus.cn`、境外 PRD `seenzus.ai`。开发入口最多四条，再加 UAT `uat.seenzus.ai`、Dev Server。普通 HA 添加界面只显示正式环境；从 UAT 应用发起可直接配对，无需开发配置文件。Dev Server 通过开发预设启用，HA 直接选择 UAT 也可用该预设开启入口。
- 一个条目连接一个环境、一个 World。同一 HA 的每个环境最多一个条目，不同 World 不能绕过此限制；所有自定义 Dev Server 地址共享一个名额。新增重复条目会在兑换凭证前拦截，引导管理原条目，不覆盖已有凭证或设备范围。
- 重新配对从原条目进入，固定原环境和 World，保留设备范围。同一环境要更换 World，需先移除原 HA 条目再重新接入，不能让两个 World 的条目共存。不同登录用户在同一 World 内仍共享同一 Source。
- 应用发起的新配对自动传递环境，不要求复制粘贴引导码。HA 直接添加时可选择环境。自动识别缺失或过期时允许手选一次，绝不默认为境外 PRD。
- 环境和 API 地址保存在条目。全局 `seenzus_bridge_dev.json` 只提供开发入口或预设，不能修改其他条目，不能在重配对时覆盖已绑定环境。
- HA 管理员按条目选择全部设备或指定设备；区域只帮助批量选择，不是动态扩张的权限规则。明确选择的设备可以共享给多个条目，包括管理方和可控制设备的 UAT。
- 指定设备清单不会自动纳入新增设备；设备重命名不丢失授权。独立实体需要同样明确的授权入口。
- 权限同时约束目录、状态、按需读取和控制，不只是隐藏 UI。无法验证目标范围的脚本、场景、模板、任意事件和全局操作不开放给受限条目。HA 管理员配置的底层自动化仍需遵守租户边界；共享 HA 不构成进程或故障隔离。
- 撤回授权后停止新数据及控制，从当前可用设备中移除；已有历史、日志和记忆保留。撤权和设备离线是不同状态。
- 单一 World 内多个地点沿用 Seenzus 现有 Site 管理，无须按地点建立多个桥条目。

## 无手输的配对衔接

HA 官方 `config_flow_start` 只透传 `domain`，不能依赖自定义 `env` query、Referer 或 window.opener。采用一次性浏览器上下文加 HA external step：

1. 应用在配对使用的浏览器或隔离 WebView 中，先访问固定的 Seenzus 中转页，保存有期限的发起环境，再进入官方 HA 配置入口。
2. HA 管理员配置流准备设备授权、注册回调并生成绑定该 flow 的短期 state。首次零条目也从这个标准入口开始，不能直接导航到尚未注册的自定义 view。
3. 外部步骤回到中转页，读取同一浏览器上下文。若 HA 已有目标环境条目，显示管理原条目的提示；否则进入目标环境创建会话和完成 World／地点授权。不得让来源提示替代登录及授权；HA 在兑换凭证前也会独立检查环境是否重复。
4. 最终回调绑定环境、session、code 和 HA state；桥只向可信环境兑换凭证并建立或更新对应条目。
5. 浏览器用 Web Locks 串行处理待办，不覆盖另一个未完成的发起记录。记录有效期为 10 分钟；HA state 带发起时间及 15 分钟到期时间。旧 HA 窗口不能认领后来创建的待办；时钟不一致时退回手选。已认领的 state 只复用原来的环境。
6. HA 内同时只允许一个配对流程兑换凭证；其他条目等待前一个流程完成或取消。过期或取消的回调不能显示成功；已确认完成的重复回调不再次配对。
7. 环境记录只是导航提示，不授予权限。授权页显示实际部署环境和当前 World，多 World 的 owner 可切换后授权。World 来自目标服务器上的已登录身份，重配对还必须满足原 World／旧 Source 约束。

中转域名固定为 `https://app.seenzus.cn/ha-connect`。中转域名在国内外的可达性、HA 局域网地址、普通浏览器及 App WebView 的存储和窗口行为需要实际部署验证。无手输是要求；浏览器弹窗受限时 HA 原有的“打开网页”按钮仍可作为兜底。

HA 官方跳转不会保留最初的应用 launch ID，因此浏览器提示与 HA flow 不是端到端签名绑定。当前通过单待办、时间顺序检查、HA 配对串行以及授权页显式展示环境／World降低混淆；不要把环境提示作为身份依据。比如另一个 HA 的直接入口恰好在待办存在期间选择“跟随应用”，可能沿用该提示，用户仍需在目标环境确认 World。需要完全排除这种情况时，应在 HA 直接入口明确选环境。

## HA 管理员操作

添加桥时可选全部设备或指定设备。已有条目从「设置 → 设备与服务 → Seenzus Bridge → 对应条目 → 配置 → 设备授权范围」修改。区域会一次性展开当前设备及独立实体；不是持续授权整个区域。设备使用 HA device registry ID，独立实体使用 entity registry ID，重命名不改变授权。空的指定清单代表全部撤权。

默认快速配对逐页展示「配对方式 → 授权范围」，跳过环境页，后续中转页自动沿用应用发起记录；没有记录或记录失效时才补选环境。HA 官方跳转不透传来源参数，因此直接从 HA 发起的默认快速配对也使用这一路径。中转页不可用（如尚未部署）导致授权步收不到回调时，流程在完成步回退到桥内补选环境，与中转页口径一致，绝不默认境外 PRD。在位配对流程停在外部授权步等待回调期间，新的主动配对可以接管唯一配对槽并终止停在那里的流程；未停在外部授权步的在位流程仍然照常独占槽位。需要提前指定环境（包括 Dev Server）时，在首屏选择「快速配对（手动选择环境）」；手动填写 MQTT 配置也先选环境。选择指定设备后，再依次进入「选择设备 → 选择独立实体」，全部设备则跳过这两页。设备页的区域选择仅加入当前设备；独立实体页的区域选择仅加入当前未归属设备的注册实体。选择整台设备已包含其下实体，无需重复选择；两页均可留空。复制插件到 HA 时须包含 `translations/zh-Hans.json`，重启 HA 并在新页面重新发起配置，以读取新的中文标题和字段名。

设备范围变更不要求重新配对。设备范围之外的读取、事件和命令由本地桥拒绝；云端收到新的授权目录后更新当前可用设备视图。断网期间云端无法立即获知 HA 的更改，恢复后由目录同步更新。

指定设备模式只开放能够核验明确 entity_id 目标的服务。脚本、场景、分组／模板实体、任意事件和无法确定目标范围的服务被拒绝；允许的普通实体也可能触发管理员自行设置的 HA 自动化，不能据此宣称物理租户隔离。

## 发布顺序与兼容

1. 先备份并验证应用迁移 `0225_bridge_device_access.sql`，为 Source 链接增加独立撤权状态及证据时间。
2. 部署三个应用环境的 API 和页面，确认国内中转页以及各环境 `/pair/bootstrap` 可达；旧插件仍沿用原协议。
3. 验证从 UAT／国内／境外各自发起的真实浏览器和手机链路，再更新 HA 插件。
4. 旧条目自动迁移为原连接地址、原凭证、全部设备授权。不会重新解释开发配置文件；缺少 World 身份的旧条目在下一次重配对时通过原 Source 校验补齐。
5. 不应仅回滚到旧版桥并声称保留设备范围隔离。旧版不执行新授权规则；必要时先停用受限条目再回滚。云端不会因缺少新 access 字段的旧目录而清除已保存的撤权记录。
